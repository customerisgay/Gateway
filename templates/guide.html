Part I — Getting your first payment

Connect a payment provider and create your first payment link.

1

Create your account

Create an account with your email and password.

2

Pick your rail

Not sure? Start with FamPay if you already receive FamPay UPI — it's fully automated and costs nothing.
3

Connect FamPay

Dashboard → Payments → FamPay. You'll need three things:

  1. The Gmail address that receives your FamPay payment-confirmation emails.
  2. A 16-character Google App Password (not your Gmail password): Google Account → Security → 2-Step Verification → App passwords → create one named “Godpay”. Enable IMAP in Gmail settings.
  3. Your FamPay UPI ID (e.g. yourname@fam).

Paste them in and hit Test IMAP connection — it checks the credentials you just typed, before you save. You should see “Connected — INBOX has N messages.” Then enable FamPay and save.

App Passwords require 2-Step Verification. Without it Google won't issue one — and FamPay will look “broken” when it's really just the password.
4

Connect BharatPe

  1. Open enterprise.bharatpe.in → DevTools → Network tab → reload → click any request to payments-tesseract.bharatpe.in.
  2. Copy the merchantId query parameter → paste as Merchant ID.
  3. Copy the token request-header value → paste as API token.
  4. Your collect VPA is the UPI ID printed on your BharatPe QR standee (usually ends in @unitype / @yesbank).

Hit Test BharatPe API — it calls the feed with what you typed. Then enable and save. Godpay polls every ~5s and matches by exact amount.

5

Official gateways (optional)

Already run Razorpay / PhonePe / Paytm / Cashfree / MobiKwik? Dashboard → Payments → Official gateways → paste your merchant keys → Test connection (leave secret fields blank to keep saved credentials).

Official gateways need your own merchant account with that gateway. Godpay orchestrates — creates the payment, verifies the signed callback, settles the order — it never holds your money.
6

Take a ₹1 live payment

  1. Dashboard → Orders is empty — good. Go to API Keys → Generate key → copy your fp_live_ secret (shown once).
  2. Ask your site/bot to call POST /api/v1/order/create with {"amount": 1} — or use the curl in Part II-B.
  3. Open the returned payment_url on your phone, pay ₹1.00-something from any UPI app.
  4. Watch the order flip to PAID — usually within seconds (BharatPe) or a few minutes (IMAP poll).
That's the whole loop: create → pay → auto-verify → PAID. Your webhook (if configured) fires the same moment.
7

Go-live checklist

  • Live rail connected and tested (steps 3–5)
  • HTTPS webhook URL registered in Dashboard → Webhooks — you verify X-FamGate-Signature (Part II-C)
  • SMTP configured on the server if you want customer receipt emails
  • Rate limits understood (Part II-E) — create: 60/min, status: 180/min per key
  • ₹1 live order settled end-to-end

Part II — Developers

See the API reference for endpoint details.

A. Authentication

Every call carries your key. Generate one at Dashboard → API Keys.

X-Api-Key: fp_live_your_key_here
# or
Authorization: Bearer fp_live_your_key_here

B. Create an order

curl -X POST {{ base }}/api/v1/order/create \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: fp_live_your_key_here" \
  -d '{ "amount": 250, "order_id": "INV-2026-991", "customer_name": "Rohan Gupta", "note": "Pro Plan" }'

Response includes payment_url (send the customer there, or embed it), upi_link (direct UPI deep link) and qr_base64 (render your own QR). exact_amount includes a paise offset for collision-free matching — display the amount your customer sees, exact_amount, not the pre-offset one.

C. Webhooks & signatures

After verification, Godpay sends:

POST https://yourapp.com/webhooks/famgate
X-FamGate-Signature: sha256=<hex hmac>

{ "event": "payment.verified", "order_id": "ord_…", "provider": "fampay",
  "amount": 250.42, "currency": "INR", "utr": "412345678901",
  "payer_name": "ROHIT KUMAR", "client_ref": "INV-2026-991",
  "customer_name": "Rohan Gupta", "customer_email": "rohan@example.com",
  "note": "Pro Plan", "paid_at": 1762950000 }

Verify it with your webhook secret (Dashboard → Webhooks → reveal):

# Python
expected = "sha256=" + hmac.new(SECRET.encode(), raw_body, hashlib.sha256).hexdigest()
assert hmac.compare_digest(expected, request.headers["X-FamGate-Signature"])
// Node
const expected = "sha256=" + crypto.createHmac("sha256", SECRET).update(rawBody).digest("hex");
if (expected !== req.headers["x-famgate-signature"]) return res.sendStatus(401);
Use the raw request body for the HMAC — any JSON re-serialization breaks the signature.

D. Poll order status (fallback)

Webhooks are push; this is the pull fallback if your endpoint is temporarily unreachable:

curl "{{ base }}/api/v1/order/status?order_id=ord_9f8e7d…" -H "X-Api-Key: fp_live_…"
# or by your own reference: /api/v1/order/status?client_ref=INV-2026-991

Returns status: PENDING | PAID | EXPIRED | CANCELLED, plus utr when paid.

E. Errors & limits

400validation — check the error message, it says the field 401missing / revoked API key 404unknown order (or belongs to another merchant) 409UTR already claimed by another order 429rate limited — back off (create 60/min · status 180/min · per-IP 300/min) 502upstream (BharatPe / gateway) error — retry with jitter
Something broken at the rails? The dashboard shows Provider health on the overview page — a red dot there beats any stack trace.
