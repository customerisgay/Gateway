1. Authentication

Every API call uses your key in the header. Generate one at Dashboard → API Keys.

X-Api-Key: fp_live_your_key_here
# or
Authorization: Bearer fp_live_your_key_here

2. Payment flow

1Your server calls POST /api/v1/order/create 2Godpay returns a payment_url, UPI link and QR (base64) 3Customer scans & pays the exact amount shown 4Godpay auto-verifies via FamPay email IMAP / BharatPe feed — or, for official gateways, via the gateway's signed webhook/status API — and marks the order PAID 5Your server is notified via webhook (payment.verified), or you poll /order/status

3. POST /api/v1/order/create

Creates an order and returns everything you need to render a checkout.

curl -X POST {{ base }}/api/v1/order/create \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: fp_live_your_key_here" \
  -d '{
    "amount": 250,
    "order_id": "INV-2026-991",
    "provider": "auto",
    "customer_email": "rohan@example.com",
    "customer_name": "Rohan Gupta",
    "note": "Pro Plan Renewal",
    "expiry_minutes": 15
  }'

Response 200:

With an official gateway (e.g. "provider": "razorpay") the same call returns payment_url (gateway-hosted checkout, or our status page for Paytm/MobiKwik that boots their checkout), an empty upi_link, and exact_amount == amount. The returned order settles automatically once the gateway's webhook confirms payment — or on the next status poll.

3a. Official gateways (Razorpay, PhonePe, Paytm, Cashfree, MobiKwik–Zaakpay)

Godpay acts as the orchestration layer, not the money-holder: you register as a merchant with the gateway, paste your keys in Dashboard → Payments (stored encrypted, Fernet/AES), and Godpay creates payments there, verifies their callbacks, marks orders PAID and fires your webhook. Your money settles in your gateway account; Godpay never sees card data.

// Razorpay — Payment Links API (rzp_test_*/rzp_live_* keys)
// PhonePe   — Standard Checkout (merchantId + saltKey, pg-sandbox or hermes)
// Paytm     — All-in-One JS checkout (MID + 16-char merchant key)
// Cashfree  — Payment Links API (x-client-id / x-client-secret)
// MobiKwik  — Zaakpay Express Checkout V13 (merchantIdentifier + secret, HMAC-SHA256 forms)
webhooksgateways call {{ base }}/webhooks/<provider> — we HMAC/checksum-verify before touching the order. Razorpay also supports a signed GET browser callback (payment_link + payment_id + signature triple). fallbackstatus polls (every ~60s, and on /order/status) re-check pending gateway orders server-side, so a missed webhook still settles your order. GPayGoogle Pay has no merchant collection API. It is a payer app — accept it via any UPI rail above (QR/deep links, or inside a gateway checkout).

4. GET /api/v1/order/status

curl "{{ base }}/api/v1/order/status?order_id=ord_9f8e7d6c5b4a3928171" \
  -H "X-Api-Key: fp_live_your_key_here"
# or POST with JSON: {"order_id": "..."} — or look up by ?client_ref=INV-2026-991
{
  "success": true,
  "order_id": "ord_9f8e7d6c5b4a3928171",
  "status": "PAID",              // PENDING | PAID | EXPIRED | CANCELLED
  "amount": 250.0,
  "exact_amount": 250.42,
  "utr": "412345678901",          // present when PAID
  "payer_name": "ROHIT KUMAR",
  "paid_at": 1762950322,
  "time_remaining": 512
}

Status polls trigger an on-demand provider scan (throttled), so polling every 3–5s gives near-realtime confirmation.

5. POST /api/v1/order/verify-utr

Manual fallback when the customer paid the wrong amount or the auto-match window missed. UTR is de-duplicated globally — a claimed UTR can't verify twice.

curl -X POST {{ base }}/api/v1/order/verify-utr \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: fp_live_your_key_here" \
  -d '{"order_id": "ord_9f8e...", "utr": "412345678901"}'

6. GET /api/v1/orders

7. Webhooks & signature verification

Set your URL at Dashboard → Webhooks. Events: payment.verified, payment.test. Every request carries:

X-FamGate-Eventpayment.verified X-FamGate-Signaturesha256=<hex> — HMAC-SHA256 of the raw request body, keyed with your webhook secret

Python:

import hmac, hashlib

def famgate_valid(raw_body: bytes, sig_header: str, secret: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, sig_header or "")

Node.js:

const crypto = require('crypto');
const expected = 'sha256=' + crypto.createHmac('sha256', SECRET).update(rawBody).digest('hex');
const ok = crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(req.headers['x-famgate-signature'] || ''));

Respond with any 2xx within 10s. Delivery attempts and response bodies are logged at Dashboard → Webhooks. Always verify the signature and idempotency on order_id.

8. The decimal-offset contract

With decimal offset enabled (default), Godpay quotes ₹100 as e.g. ₹100.42. The paise are the order's fingerprint: a hundred concurrent ₹100 orders each get a different offset, and incoming money is matched deterministically — zero collision, no customer typing UTRs. Show the exact amount big and bold with a one-tap copy button (the hosted checkout does this for you). Disable in Dashboard → Payments if you accept manual-UTR matching instead.
